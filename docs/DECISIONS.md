# Decisions

Small defaults chosen without asking (brief §1). One line each; anything expensive to undo is an ADR in `docs/adr/` instead.

- 2026-11-02 — Solution file is classic `ArduSim.sln` (as named in the brief), not `.slnx`.
- 2026-11-02 — `global.json` pins SDK 10.0.100 with `latestFeature` roll-forward; all projects target `net10.0` (`net10.0-windows` for the App).
- 2026-11-02 — NuGet versions are managed centrally in `Directory.Packages.props`; shared MSBuild settings in `Directory.Build.props`.
- 2026-11-02 — Analyzers at `latest-recommended` everywhere; `TreatWarningsAsErrors` only in Core, Build and Ipc (brief). CA2007 (ConfigureAwait) is off: this is an application.
- 2026-11-02 — Tests use xUnit v3 on Microsoft.Testing.Platform (`global.json` `test.runner`), as required by the .NET 10 SDK for xUnit v3; run with `dotnet test`.
- 2026-11-02 — `ArduSim.Build.Tests` ignores the "zero tests" exit code until its first test lands in M1.
- 2026-11-02 — The App references the Runner project: it hosts the in-process session and puts `ArduSim.Runner.exe` next to the App.
- 2026-11-02 — `ISimulationSession` lives in `ArduSim.Ipc` next to the contracts it uses.
- 2026-11-02 — Virtual time is kept in nanoseconds internally (`ulong`), exposed to firmware in µs.
- 2026-11-02 — UI strings: `Resources/Strings.resx` with Russian as the neutral language, read through `{l:Loc Key}` and `Strings.Get`; missing keys render as `!Key!`.
- 2026-11-02 — Icon set: Fluent UI System Icons (MIT), Regular style, as path geometry.
- 2026-11-02 — UI font: Segoe UI Variable with Segoe UI fallback; nothing bundled.
- 2026-11-02 — Logging: `Microsoft.Extensions.Logging` API with Serilog as provider; log files are written with the invariant culture.
- 2026-11-02 — Firmware debug info is CodeView/PDB, symbolized with the in-box `dbghelp.dll` (without `SYMOPT_DEFERRED_LOADS`, which breaks line lookup for these PDBs).
- 2026-11-02 — The shim never exposes `<windows.h>` to sketch translation units.
- 2026-11-02 — Dev-only scripts live in `tools/` (toolchain evaluation, Nano timing bench); they are not part of the build or tests.
- 2026-11-02 — Git: `main` branch, conventional commits.
- 2026-11-02 — The brief is kept in the repo as `docs/BRIEF.md` so a clean clone carries its own specification.
- 2026-11-02 — Shim `min`/`max` are templates in C++ (ArduinoCore-API style) so the C++ standard library stays usable; `round()` is the C library's (returns double; the AVR macro returns long).
- 2026-11-02 — `word` is `uint16_t` as on AVR, even though `int` is 32-bit.
- 2026-11-02 — `pgm_read_word`/`pgm_read_dword` through a pointer-typed address return the whole 64-bit pointer, so PROGMEM string tables work unchanged.
- 2026-11-02 — `EEMEM` variables fail at compile time with a clear message (they need linker-placed EEPROM addresses).
- 2026-11-02 — Direct port reads/writes cost one `digitalRead`/`digitalWrite` per changed bit (no ABI call for whole ports yet).
- 2026-11-02 — Libraries the shim provides (EEPROM now, Wire/SPI later) resolve before every other library root, since they are tied to the simulated hardware.
- 2026-11-02 — Library detection is textual (no preprocessor pass); an include inside an inactive `#if` still pulls its library in. Revisit if a bundled library trips on it.
- 2026-11-02 — Each return from `loop()` costs 1 µs of virtual time (main()'s loop overhead), so an empty `loop()` still lets time pass.
- 2026-11-02 — At most one ISR is dispatched per scheduling point, so a LOW-level interrupt cannot starve the host.
- 2026-11-02 — A run ends with `TerminateProcess` after flushing output, so the sketch's static destructors never call into a shutting-down runtime.
- 2026-11-02 — Headless runs default to `--speed max`; the watchdog ends a headless run that is busy without API calls for 2 s (exit code 3).
- 2026-11-02 — Runner exit codes: 0 ok, 1 build failed, 2 firmware error, 3 firmware busy, 64 usage, 69 toolchain unavailable, 70 internal error.
- 2026-11-02 — Build output goes to `%LOCALAPPDATA%\ArduSim\builds\<project>-<hash>` (override with `--build-dir`), keeping project folders clean.
- 2026-11-02 — The project file model lives in `ArduSim.Core.Projects` (plain data, System.Text.Json).
- 2026-11-02 — The toolchain is extracted with System.IO.Compression (no external tools); the first install takes about 2.5 minutes here, mostly extraction.
- 2026-11-02 — Integration test fixture projects live in `tests/ArduSim.Integration.Tests/Projects`; `examples/` holds only user-facing examples.
- 2026-11-02 — Net resolution: strong drivers must agree within 0.5 V (else a short); weak sources and sources behind resistors combine as a Thevenin equivalent over the shortest resistor path; a strongly driven net clamps the search. No currents.
- 2026-11-02 — INPUT_PULLUP is a 35 kΩ weak source; inputs read HIGH from 0.6 Vcc and LOW up to 0.3 Vcc, undefined (warning, random) in between.
- 2026-11-02 — An LED lights when forward-biased by sources of at most 10 kΩ; brightness is the PWM duty. The Nano's on-board L LED is buffered, so it follows the D13 voltage alone.
- 2026-11-02 — Part state is a string → number map (`brightness`, `pressed`, `value`, `frequency`, `L`), the same in Core, IPC snapshots and the view.
- 2026-11-02 — Part classes expose their definition as `public static ComponentDefinition Spec`; the board part is generic and built from the board profile.
- 2026-11-02 — `SimCrashInfo.exception_code` is named `exception_status` (`exception_code` is a macro in `<excpt.h>`); `return_address` and `access_kind` were appended. Layout-compatible, nothing shipped, so the ABI stays 1.0.
- 2026-11-02 — The shim's exception handler terminates the process right after recording a crash, so the app shows the report in milliseconds instead of waiting for .NET and Windows Error Reporting.
- 2026-11-02 — The busy-firmware exit code is 4 (3 is what `abort()` returns).
- 2026-11-02 — In-process sessions load a private copy of firmware.dll per run and park a stopped run's thread (native frames cannot be unwound).
- 2026-11-02 — The App references Core directly for scene data and part definitions (read-only).
- 2026-11-02 — M2 draws parts with XAML templates in MainWindow (handlers stay view glue); definition-driven vector art and the editor arrive with M3.
- 2026-11-02 — The M2 canvas fits the scene with a Viewbox; pan and zoom arrive with the M3 editor.
- 2026-11-02 — Headless `--input <ms>:<part>:<name>=<value>` schedules part inputs, so tests can press buttons.
- 2026-11-02 — Part art is a XAML template per part type in `App/Themes/Parts.xaml` (keyed `Part.<type>`), not vector data in Core definitions; ADR-007 keeps definitions and behaviour together, the look stays in the App.
- 2026-11-02 — Canvas units are 0.01 inch; 100 % zoom draws 2 px per unit. Hit testing runs on view-model geometry (part bounds, pin positions, route segments), not on WPF visuals.
- 2026-11-02 — Undo is a snapshot of the whole scene per step (scenes are small); a drag is one step.
- 2026-11-02 — Boards are picked in the toolbar, not placed from the palette; the board part cannot be deleted.
- 2026-11-02 — Icons use the Windows icon font (Segoe Fluent Icons, Segoe MDL2 Assets on Windows 10) instead of shipping the Fluent UI System Icons package: the same design family, nothing to bundle.
- 2026-11-02 — Dragging a wire segment turns every bend of its route into an explicit waypoint; a segment that ends on a pin gets a waypoint at the pin so the pin stays put.
- 2026-11-02 — Recent projects and the panel layout live in `%LOCALAPPDATA%\ArduSim\ui-state.json`; an unreadable file means defaults.
- 2026-11-02 — A new project is created in the folder the user picks (created if needed): `project.simproj.json` and `sketch/<folder name>.ino` (non-identifier characters become `_`); a folder that already holds a project is opened instead.
- 2026-11-02 — Code tabs open every sketch source file (`.ino` first); a closed tab is reopened from the "+" menu.
- 2026-11-02 — Build saves the open files; Run also saves the scene and settings, because the Runner reads the project from disk.
- 2026-11-02 — Log messages that share a code carry a variant (`scene.duplicate-id`); the resource key is `Log_<code>[.<variant>]`, arguments formatted invariantly as the English pattern asks.
- 2026-11-02 — The properties panel shows a choice with swatches when it is a color, a segmented control up to four options, otherwise a dropdown (docs/UI.md §2.4).
- 2026-11-02 — LiquidCrystal_I2C 1.1.2 has no license; the owner decided to bundle it as distributed through the Arduino Library Manager (sources only, the repository's prebuilt `.o` left out). To be settled before a public release.
- 2026-11-02 — Wire follows the AVR TwoWire: write() past 32 bytes returns 0 and the bytes are dropped (with one warning), a NACK always ends with STOP, `endTransmission(false)` makes the next start a repeated start. Slave mode and `onReceive`/`onRequest` warn that they are not simulated.
- 2026-11-02 — `Wire.begin()` turns on the internal pull-ups of SDA/SCL, as the AVR core does. The pull-up note fires when the bus source resistance is above 20 kΩ (only the ~35 kΩ internal ones); LCD backpacks carry 4.7 kΩ to their VCC.
- 2026-11-02 — Wire calls before `Wire.begin()` warn once and still work (a real board would hang).
- 2026-11-02 — I2C NACK warnings are per address and say why: nothing on the bus, a device with that address wired to other nets, or SDA/SCL swapped.
- 2026-11-02 — The HD44780 executes a command that arrives while busy and warns once (a real controller may drop it), so a timing slip in a sketch is visible but not fatal.
- 2026-11-02 — The HD44780 has pull-ups on RS, RW and D0-D7 (about 50 kΩ); the 4-bit LCD layout hides D0-D3, which then read 1. An unconnected RW therefore reads HIGH (read mode) and writes are ignored, with a warning.
- 2026-11-02 — LCD contrast: V0 at 0 V is darkest, about 2 V and up shows nothing (VDD 5 V); with V0 unwired, and on I2C backpacks, the `contrast` property applies. The parallel backlight is on when A is at least 2.5 V above K.
- 2026-11-02 — 5x10 font mode is accepted and drawn as 5x8; 1-line mode shows only the first row of the glass.
- 2026-11-02 — The A00 character ROM is drawn by hand after the datasheet table (7 rows per glyph, 0xFF fills all 8); small pixel differences from a given physical ROM are possible.
- 2026-11-02 — Part size and pins may depend on properties: `ComponentDefinition.Layout` returns one cached definition per layout. Changing such a property removes wires to pins that no longer exist, in the same undo step.
- 2026-11-02 — Palette presets are `ComponentPreset`s (id, name, property values); a drag carries `type#preset`.
- 2026-11-02 — Display frames ride in `ComponentUpdate.Display` (optional, appended): character LCDs send rows x 8 lines of 5-bit cells, status bits and contrast. Old and new fields are compatible, so the IPC protocol version stays 1.
- 2026-11-02 — The headless Runner prints display text 20 ms of virtual time after a change, so text written character by character shows up once; CGRAM glyphs print as `\0`-`\7`, other non-ASCII codes (and ¥ 0x5C, `"`) as `\xNN`.
- 2026-11-02 — Builds pass core and library include folders as `-isystem` to the sketch and compile library sources with `-w` (the Arduino IDE's default "warnings: none" for libraries); the sketch's own warnings still show.
- 2026-11-02 — The LCD glass is a WriteableBitmap drawn at the zoom's resolution (whole-pixel dots, never larger than they appear, at most 4 px per canvas unit) and shown at a fixed glass size with nearest-neighbor scaling, so it is only ever scaled up by less than a dot (brief §3.5).
- 2026-11-02 — The run's wall clock, pacer and watchdog start before the firmware DLL loads, because static constructors may already call the Arduino API.
- 2026-11-02 — Hardware SPI: a byte goes to the one device whose CS net is LOW; with none selected the MCU reads 0xFF, with several it warns about the conflict. Modes 1 and 2 warn, because the device models sample MOSI on the rising edge (modes 0 and 3). The clock is the fastest F_CPU/2…/128 not above the request, 8 bit times per byte. `SPI.begin()` makes SCK, MOSI and SS outputs (SS HIGH if it was an input), as the AVR core does; transfers before `begin()` warn once and still work.
- 2026-11-02 — Bit-banged SPI (the Adafruit and U8g2 software-SPI constructors) needs no bus code: an OLED on SPI watches the rising edges of its own D0 pin and shifts D1 in, so any pins work.
- 2026-11-02 — OLED modules are wired the way the common boards are, so the libraries' usual init (segment remap A1, COM scan C8) shows an upright picture: 128x64 alternative COM pins, column offset 0; 128x32 and 96x16 sequential; 64x48 column offset 32; SH1106 1.3" offset 2 of 132 columns. Glass row and column come from the controller's scan, remap, offset and start line, so a wrong init shows as on hardware (mirrored, shifted, half height).
- 2026-11-02 — SSD1306 scrolling rewrites GDDRAM as the chip does (after 0x2E the shifted picture stays until redrawn), one step per frame-interval setting of the frame clock: fosc / (D · K · MUX) with fosc = 300 kHz + 8.75 kHz per oscillator step and K = phase 1 + phase 2 + 50.
- 2026-11-02 — An SH1106 ignores SSD1306-only commands (0x20–0x22 addressing mode and ranges, 0x8D charge pump, 0x26–0x2F and 0xA3 scrolling, 0xD6 zoom) without a log entry, because U8g2 and other libraries send them to both; other unknown commands log one info entry per code.
- 2026-11-02 — An OLED module needs VCC of at least 3.0 V and GND at most 0.5 V (warning otherwise, display dark); RES held LOW resets the controller. The I2C module carries 4.7 kΩ pull-ups to its VCC like the common boards.
- 2026-11-02 — OLED pixels on the canvas are whole device pixels (1–8 per OLED pixel, rounded from the zoom) with a dark gap from 4 px up; unlit pixels are transparent so the glow follows only the lit ones. Panel colors: white #F0F5FF, blue #48AEFF, yellow-blue with the top 16 rows #FFD447; brightness 0.35 + 0.65 · contrast.
- 2026-11-02 — Headless `--dump-display <file>.png` writes each display at the end of the run as a grayscale PNG (OLED 1:1, LCD as the dot glass); with several displays the files are `<file>-<id>.png`. Display lines in the log are `oled1: N px on`.
- 2026-11-02 — `examples/OledAdafruit` is the library's `ssd1306_128x64_i2c.ino` unmodified; its scene puts the module at 0x3D, the address that sketch uses for 128x64. `examples/Sh1106` uses Adafruit_SH110X over hardware SPI. `examples/Potentiometer` covers the brief §7 item on `analogWrite` and the Serial Plotter.
- 2026-11-02 — U8g2 is vendored from the U8g2_Arduino repository at tag 2.37.1 (bb6ebd1), whose `library.properties` still says 2.36.19; THIRD_PARTY records both.
- 2026-11-02 — Serial Plotter: the Arduino IDE's line format (values separated by spaces, tabs or commas, optionally `label:value`; unnamed values are named by position), the last 500 lines, a value missing on a line is a gap. The value axis is rounded out to at most six ticks of 1, 2, 2.5 or 5 × 10^k.
- 2026-11-02 — Light theme: the token dictionary is swapped at runtime (`Themes/Dark.xaml` ↔ `Themes/Light.xaml`, the light values of docs/UI.md §3.1), so XAML uses `DynamicResource` for every color and the shadow; code-side colors (canvas grid, editor syntax and markers, ground wires, plotter) follow `Theme.Changed`. Light syntax colors are at least 4.5:1 on the light editor background. The choice is in Параметры and is kept in `ui-state.json`.
- 2026-11-02 — The examples gallery shows each example's scene, rendered by an offscreen `SchematicCanvas` at idle priority after startup and again after a theme change; the start view columns are 2:3 so three cards fit per row.
- 2026-11-02 — "О точности симуляции" is a modal side sheet over the right edge of the window with ten limits (types, time, interrupts, registers, sketch errors, memory, buses, circuit, displays, sleep/watchdog); README lists the same.
- 2026-11-02 — The status bar's actual speed is measured over the last second of wall time, not averaged since the start, so a speed change shows within a second.
- 2026-11-02 — A scene change that keeps the same wires (a drag) updates the wire views in place and keeps unchanged routes and brushes (one frozen brush per color), so only moved wires redraw: 22 → 60 fps when dragging in a 50-part, 200-wire scene.
- 2026-11-02 — Performance on the dev machine (Intel Arc A580, hardware rendering, Debug build): 4 M host calls/s (target 2 M, checked by `PerformanceTests`); canvas 60 fps zooming or dragging with 50 parts and 200 wires; App working set 234 MB with the Adafruit OLED example running and 278 MB with the 50-part scene (target 300 MB; about 140 MB of it is the GPU driver: 170–195 MB with software rendering), Runner 60 MB. The canvas and memory numbers come from offscreen scenario runs of the window, not from `dotnet test`.
- 2026-11-02 — `tests/ArduSim.App.Tests` (net10.0-windows) tests App view-model logic without a window.
